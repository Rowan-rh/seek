# 调查模式

本页按通知、告警和外部依赖场景按需加载。它提供取证路径和常见模式，不替代当前链路的 `requiredInputs`、`outputs` 与 `constraints`。

## 通知未送达：先判断请求是否生成

“用户没收到”不能直接归因于通知平台。按顺序确认：

1. 用 uuid、sname、ali_uid、告警时间、渠道和接收目标定位事件；中文长标题拆成短词检索。
2. 检查通知组匹配结果，例如 `hitRecords`。
3. 分开检查手工静默、自动收敛和 DROP 丢弃：
   - `silenceRuleIdList` / `match silence rule`：手工静默；
   - `Already isRestrain`：自动收敛；
   - `this alarm has been dropped`：DROP，通常表示通知请求未生成。
4. 只有确认上游未拦截后，才查询 notice-service、下游任务 ID、Roar 回执、值班表和接收人。

上游未生成通知时，不应继续把问题归因到发送、运营商或接收端。

## 外部接口返回语义

外部接口返回 `Success` 可能只代表请求被受理，不代表业务完成或用户已经收到。需要：

- 读取本地 SDK sources jar 或接口定义，确认返回值语义；
- 从响应和日志中提取下游任务 ID（例如 `queryId`），作为跨团队反查凭证；
- 使用 `seek notify query <queryId>` 查询触达状态，并记录查询留存边界；
- 将“受理”“执行”“送达”分别作为独立状态，不合并成一个成功结论。

`roar noti-query` 仅支持近 7 天数据。查询不到时，先确认 queryId、事件时间和查询窗口都在保留期内，再决定是否记录为平台侧未实际投递。

## 电话通知常见模式

| 模式 | 证据特征 | 结论边界 |
|---|---|---|
| 终端拦截 | 平台有发送记录，触达状态失败或运营商回执表示未接听/无法接通 | 可定位到触达/运营商阶段，不能直接断言平台故障 |
| 值班表未同步 | 发送目标与当前值班人不一致，或无有效接收人 | 需要核对配置版本、同步任务和实际接收人 |
| 平台未发出 | 请求受理但无下游任务 ID，且上游生成证据和留存窗口已核实 | 只能在查询范围完整时下结论 |

内部状态码和运营商回执码以 `seek notify query` 返回的 `deliveryStateDesc` 为准，不要只凭历史记忆解释数字。

## 钉钉消息时间窗口语义

`seek dingtalk messages --time` 的语义是「**从该时间点开始往现在拉**」（等价 `--direction newer`），**不是「最近 N 条」**。指定窗口内该群无人发言时返回 0 条 + `hasMore=false`，这是数据语义，不是命令故障。

- 取证时用宽时间窗（如 `"2024-01-01 00:00:00"`）确保覆盖到消息，再用 `--limit` 收敛条数；
- 返 0 条必须先放宽窗口复验，仍为 0 才可记为「该窗口内无消息」，并写明窗口与群标识；
- 按关键词或 @ 我检索用 `seek dingtalk search`，其时间参数同样按起点语义理解；
- 窄窗口返空被当成 bug 是高频误判，放宽窗口后同群立即有消息即可证伪。

群 ID、消息原文和发言人属单次排查证据，只写入当次排查报告，不沉淀到本页或入口文档。

## 无 SLS/DMS 时的 fallback

对于没有 SLS 和 DMS 的项目，可以使用钉钉消息中的截图或媒体作为辅助证据：

1. 用宽时间窗检索群消息；
2. 提取 `mediaId` 和 `openMessageId`；
3. 按当前 `dws ... --help` 确认的参数下载媒体；
4. 使用 OCR/视觉模型提取异常栈，并在报告中注明证据来自截图。

下载参数若只来自 help 推断，首次使用必须在测试群小流量验证，不能把未亲测流程写成稳定事实。截图证据应保留消息时间、群、消息 ID 和原始文件位置。

## 告警富化

告警字段缺失、tag 为空或内容不正确时，先判断是富化路径还是上游直采路径，再检查富化服务、管道和字段差异。结论至少绑定：

- 告警 uuid/请求标识；
- 来源路径证据；
- 富化前后字段对比；
- 处理时间线和对应服务日志。

如果来源路径未确认，不要直接把缺失字段归因于富化服务。
