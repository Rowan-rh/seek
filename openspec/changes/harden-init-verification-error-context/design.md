## Context

当前初始化报告已经把本地配置状态与 A1/DMS 的在线验证字段分开，但聚合逻辑把所有集成的 `verified` 直接纳入 `fully_ready`；SLS 只有凭据配置检查，资源活性由 doctor 负责。错误日志则在递归脱敏后只限制叶子值，容器总量没有边界。详细行为契约见本变更的 specs 文件以及 `integration-initialization` 主规范。

## Goals / Non-Goals

**Goals:**

- 让 `seek init --verify` 的 `fully_ready` 只表示 init 自己负责的检查全部成功。
- 保留 SLS 活性由 doctor 验证的边界，并让输出可诊断。
- 让错误上下文在递归脱敏时受到深度、节点和总字节预算约束。
- 保持已有命令参数、错误日志 JSONL 格式和敏感键掩码兼容。

**Non-Goals:**

- 不在 `seek init` 默认路径新增网络访问。
- 不把 SLS doctor 的完整资源探测迁移到 init。
- 不改变错误日志读取、清空或轮转接口。
- 不对外部错误消息做与本次预算无关的重写。

## Decisions

### D1. 将“init 可验证完成”与“SLS 资源活性”分层表达
保留 `ready` 表示本地配置就绪；`fully_ready` 在 `--verify` 时只聚合 A1、DMS 的在线验证和 SLS 的本地配置前置条件。为 SLS 增加明确的验证边界或状态说明，提示 doctor 是资源活性的权威入口。

替代方案是让 init 直接调用 doctor，但这会把默认初始化的轻量边界变成资源访问流程，增加耗时、权限和多环境失败面，因此不采用。

### D2. 使用有界递归状态而不是递归后整体截断
实现一个带状态的 sanitizer，沿遍历过程维护 `depth`、`node_count` 和估算的 `output_bytes`；任一预算耗尽立即返回统一截断标记。叶子字符串继续使用现有单值上限，标量类型保持原样。

替代方案是先完整构造对象再 `json.dumps(... )[:N]`，但这仍会先消耗无界内存，且可能生成非法 JSON；不采用。

### D3. 容器预算采用固定常量并集中定义
在错误日志模块顶部集中定义最大深度、节点数、总输出字节数和截断标记，测试通过模块常量验证边界。预算需足以容纳正常错误上下文，但必须明显小于可导致日志膨胀的规模。

### D4. 截断优先于失败
当上下文不可序列化、超过预算或结构异常时，错误日志仍应写入一条合法记录；仅丢弃超限分支，不让诊断日志异常覆盖原始 CLI 错误结果。

## Risks / Trade-offs

- [正常的大型响应上下文被截短] → 输出截断标记并保留错误码、命令和关键顶层字段；测试固定兼容边界。
- [预算估算与实际 JSON 字节数存在差异] → 使用 UTF-8 编码长度做统一估算，并在写入前保留整体兜底限制。
- [调用方依赖旧的嵌套非字典字符串化结果] → 只改变超限行为和递归脱敏行为；为现有嵌套对象保留结构化 JSON，并更新回归测试。
- [SLS 状态字段被下游误解] → 在初始化结果中明确 `verified` 的责任边界和 doctor 验证命令，避免把本地配置等同于资源活性。

## Migration Plan

1. 先实现状态聚合和上下文预算，补充单元测试。
2. 运行 CLI 全量测试与 `openspec validate --strict`。
3. 发布后观察初始化报告和错误日志中的截断标记；若下游依赖旧字段，只需按既有字段语义读取，不需要迁移文件格式。
4. 回滚时恢复旧聚合和 sanitizer 实现即可，已写入的 JSONL 记录仍可被现有读取逻辑解析。
