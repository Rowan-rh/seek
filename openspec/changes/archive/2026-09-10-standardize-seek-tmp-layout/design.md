# Design: standardize-seek-tmp-layout

## Context

仓库目前通过 `AGENT.md` 约束开发行为，但没有仓库级临时产物规则，也没有统一的创建入口。临时分析报告、日志、截图或中间数据可能由不同 Agent 和辅助流程生成；这些内容既不同于 seek CLI 在 `${SEEK_HOME:-~/.seek}` 下的运行状态，也不同于 `utils.py` 为原子替换创建的同目录临时文件。

## Goals / Non-Goals

**Goals:**

- 以一次任务运行作为最小隔离和清理单元。
- 让目录名称可读、可排序且在并发创建时不冲突。
- 通过标准库 helper 和机器可读输出降低 Agent 遵循规范的成本。
- 用文档和测试共同守护目录契约。

**Non-Goals:**

- 不改变 seek CLI 的 `SEEK_HOME`、会话、配置或日志布局。
- 不迁移原子写临时文件到仓库临时目录。
- 不自动移动或删除当前未跟踪文件，避免误判用户正式产物。
- 不引入后台清理服务或第三方依赖。

## Decisions

### 1. 使用按日期分组的一次运行目录

采用 `.seek-tmp/runs/YYYY-MM-DD/HHMMSSZ-<slug>-<short-id>/`。日期和时间使用 UTC，便于跨环境复现和字典序排序；短随机标识避免同秒同任务冲突。相比按文件类型全局分桶，一次运行目录能保留输入、过程、输出和日志之间的关联，也可以整目录清理。

### 2. 运行内部固定为四阶段目录

每次运行固定创建 `inputs/`、`work/`、`outputs/`、`logs/`：

- `inputs/` 保存本次任务复制或脱敏后的输入快照；
- `work/` 保存可丢弃的中间结果；
- `outputs/` 保存待审阅或待迁出的结果；
- `logs/` 保存命令日志和诊断信息。

不按扩展名分目录，因为同一阶段可能同时包含 Markdown、JSON、图片等关联文件。

### 3. 使用 manifest 描述归属

`manifest.json` 使用 schema version 1，记录 `run_id`、`slug`、`created_at`、`status` 和相对目录映射。manifest 只包含工作区元数据，不复制命令参数、环境变量或可能含凭据的输入内容。

### 4. 提供独立的仓库开发 helper

新增仓库级 Python 脚本而不是 seek CLI 子命令。该规范服务于仓库开发和 Agent 工作过程，不是 seek 产品运行时能力；放入正式 CLI 会混淆 `.seek-tmp` 与 `SEEK_HOME`。脚本只使用 Python 标准库，默认根据脚本位置解析仓库根目录，并以 JSON 返回路径。

### 5. 文档约束与自动测试并用

`AGENT.md` 规定强制使用边界，根 README 展示目录；测试验证 helper 输出、目录结构、碰撞安全、失败清理以及 `.gitignore`/文档关键契约。相比只增加文档，这能及时发现实现漂移。

## Risks / Trade-offs

- [UTC 日期与开发者本地日期在午夜附近可能不同] → 路径和 manifest 明确使用 UTC，并以完整时间戳消除歧义。
- [运行目录长期累积仍会占用空间] → 以运行目录为清理单元，并明确正式产物必须迁出；自动保留策略留待有真实容量数据后设计。
- [Agent 绕过 helper 直接写文件] → 在 `AGENT.md` 中将 helper 设为默认入口，并用根目录禁止平铺的显式规则降低歧义。
- [误把正式产物放入忽略目录导致丢失] → 文档要求交付前迁移到正式目录，并在 manifest 中将初始状态标记为 `active`，强调其临时属性。

## Migration Plan

1. 添加 `.seek-tmp/` 忽略规则、helper、测试和文档。
2. 后续新任务统一通过 helper 创建运行目录。
3. 当前已存在的未跟踪文件不自动迁移；由文件所有者确认其临时属性后，按任务移动到新结构或移入正式目录。
4. 回滚时可删除 helper 和文档规则；`.seek-tmp` 本身不受版本控制，不影响源码或 CLI 运行状态。
