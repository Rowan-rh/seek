# Design: add-report-date-naming

## Context

- 报告由 agent 按 `SKILL.md` 排查规则第 5 条在链路 `completed` 后产出，CLI 本身不生成报告文件；落盘位置为 `stability-locate/doc/`（工作区外），目录内已有 7 份单案例报告 + 1 份 digest 汇总。
- 命名现状为隐性三段式（场景-ID-现象），无日期；digest 汇总 `seek-reports-digest-2026-08-26-to-09-01.md` 结束日期缺 4 位年份，跨年区间会产生歧义。
- 引用面已核实：`references/emergency-response-patterns.md` CASE-011~013 以文件名引用 5 份报告；digest 内部 11 处引用 6 份报告（L4 通配 `seek-report-*.md` 不受影响）；7 份单案例报告之间无相互引用；归档 change 中旧文件名属历史快照。

## Goals

- 文件名自带产出日期：平铺目录 `ls` 即按时间排序，单文件引用/分享不丢时间上下文。
- 命名规则成文（SKILL.md + spec），后续报告产出不再漂移。
- 存量报告与所有引用一次性迁移，目录内不出现新旧两套命名并存。

## Non-Goals

- 不改变报告落盘目录（仍为 `stability-locate/doc/` 平铺，不按日期建子目录）。
- 不改变报告内部结构（`cli/chains/templates/generic.md`、`ticket.md` 模板不动）。
- 不为 CLI 增加报告输出路径参数（`chain context` 的 `report_template.path` 语义不变）。

## Decisions

- **日期前缀 vs 日期子目录**：选前缀平铺。前缀方案 `ls` 排序即时间序、单文件引用自带日期、与 digest 既有命名风格一致、跨文件检索无需递归；子目录方案在单日单例场景产生大量浅目录，且引用时容易丢失日期信息。
- **日期取值**：取报告产出日（落盘日），而非告警/问题发生日——排查常跨天，产出日是文件系统可判定且无歧义的锚点；问题发生时间已记录在报告头部的"排查时间"字段。本次迁移已核实 7 份存量报告的产出日与 digest 案例表时间列一致，无对齐冲突。
- **ID 段保持可选**：沿用现状——无唯一业务标识（如 template-action-deleted 案例无 ID）时省略，避免编造无检索价值的段。
- **digest 结束日期补全 4 位年份**：消除跨年歧义，与起始日期格式对齐。
- **存量全量迁移并同步改引用**：新旧并存会削弱分类效果，一次性切换成本可控（引用面已全部枚举）。

## Risks / Trade-offs

- 文件名变长约 11 字符；聊天记录、工单里出现过的旧文件名无法直接命中磁盘文件——需经 `references/emergency-response-patterns.md` 检索入口跳转，该文件的引用已同步更新，可接受。
- 产出日与问题发生日在跨天排查场景可能相差一天（如 08-31 问题 09-01 落盘）——规范明确以产出日为准，报告头部"排查时间"保留问题发生时间线，两个时间各有锚点不冲突。
